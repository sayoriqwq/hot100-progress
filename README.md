# Hot 100 进度仓

这是力扣「[热题 100](https://leetcode.cn/studyplan/top-100-liked/)」的**个人进度仓库**：记录你每道题的状态，存放你自己写的题解。

题目、分层提示、动画演示和标准题解在网站 **https://leetcode.cgent.link** 上。用 GitHub 登录网站后，它会读取你账号下的 `hot100-progress` 仓库，显示你自己的进度和题解；在网站上改的状态也会直接提交到这个仓库。

**这个仓库是唯一的数据源。** 网站从这里读你的进度和题解，在网站上改状态、从力扣同步也都直接写进这里；网站不在别处另存一份。你在仓库里改了、删了什么，就以仓库为准。

## 怎么开始

最省事的办法：打开网站，用 GitHub 登录并授权，然后在首页点「创建进度仓」。网站会用这个模板在你的账号下建好 `hot100-progress`，私有还是公开由你选，不用自己来这里操作。

想自己建、并且只让网站碰这一个仓库，也可以：

1. 点右上角的 **Use this template → Create a new repository**，仓库名填 `hot100-progress`（名字要一致，网站按这个名字找），私有、公开都行。
2. 打开网站，用 GitHub 登录。在 GitHub 的授权页面上选 **Only select repositories**，只勾 `hot100-progress`——网站只拿到这一个仓库的读写权限，碰不到你的其他仓库。

授权范围以后随时可以在 GitHub 的 Settings → Applications 里改。

## 文件规则

网站和自动检查都按下面的规则读文件，不符合规则的文件读不到。每次 push 后，GitHub Actions 里的 `check` 会检查一遍。

### 1. 进度：`progress.json`

```json
{
  "version": 1,
  "problems": {
    "1": { "status": "已通过", "updatedAt": "2026-11-14" },
    "146": { "status": "曾通过", "updatedAt": "2026-10-02" }
  }
}
```

- 键是题号（字符串），值里的 `status` 只能是下面四种之一：
  - `已通过`：通过了；
  - `曾通过`：以前通过过，需要复习；
  - `尝试过`：提交过，但还没通过；
  - `未开始`。
- 没出现在 `problems` 里的题都算 `未开始`。刚创建的仓库是空的，也就是 0 进度。
- `updatedAt` 可选，格式 `YYYY-MM-DD`。

### 2. 题解：`solutions/<语言>/<四位题号>.<题名>[.<写法>].<后缀>`

| 语言目录 | 后缀 |
| --- | --- |
| `python` | `.py` |
| `java` | `.java` |
| `go` | `.go` |
| `cpp` | `.cpp` |
| `c` | `.c` |
| `javascript` | `.js` |
| `typescript` | `.ts` |
| `rust` | `.rs` |
| `kotlin` | `.kt` |
| `swift` | `.swift` |
| `csharp` | `.cs` |

- 题号补齐到四位，题名照抄 `hot100.json` 里的 `name`，例如 `solutions/python/0001.两数之和.py`、`solutions/java/0146.LRU 缓存.java`。
- 同一道题的多种写法，在题名后面加一段写法名：`solutions/python/0200.岛屿数量.BFS.py`。
- 用力扣插件生成的 Java 文件，网站只显示 `submit region` 标记之间的代码，本地测试代码不会出现在页面上。
- 不在热题 100 里的题也可以放进来，网站暂时不显示，但不会报错。

`hot100.json` 是 100 道题的清单（题号、题名、难度、专题、重要程度、建议的文件名），新建文件时照着它取名最省事。

### 3. 尝试记录：`attempts/<四位题号>.<题名>/<YYYY-MM-DD>.<序号>.<结果>.md`

每一次值得记的尝试（包括没通过的）都记一份，网站的题目页会按时间排成一条「尝试记录」时间线。

- 结果只能是 `通过`、`答案错误`、`超时`、`运行出错`、`思路不成立` 之一。
- 序号是当天的第几次，从 1 开始。例如 `attempts/0001.两数之和/2026-11-14.1.答案错误.md`。
- 文件开头用 `---` 包起来写设置：`lang` 必填，写语言目录名（`python`、`java`……）；代码不是原样提交时写 `verbatim: false`（不写就当作原样）。
- 正文用 `## ` 分节。「代码」一节里放且只放一个代码块，放原样提交的代码，不要改好了再存。其他小节随意，建议写错在哪里、怎么发现的、差在哪一步。

````markdown
---
lang: python
verbatim: true
---

## 代码

```python
class Solution:
    def twoSum(self, nums, target):
        ...
```

## 错在哪里

……

## 怎么发现的

……
````

### 4. 从力扣同步

网站的 https://leetcode.cgent.link/sync/ 可以把你在力扣中国站上的提交记录写进这个仓库：每次提交一个 `attempts/` 文件，状态也跟着更新，所有改动合成一个 commit，你确认后才写入。不用装东西：把页面上的「同步力扣」按钮拖到书签栏，在 leetcode.cn 上点它就行。

同步来的记录在开头的设置里多三项，手写的记录也可以照着写：

```markdown
---
lang: python
verbatim: true
source: leetcode.cn             # 从哪里来
submission: 700580689           # 力扣的提交编号，只写数字
submittedAt: 2026-11-14T10:05:00+08:00
---
```

- 同步靠 `submission` 判断一次提交有没有导入过，所以同一个编号只能出现在一个文件里，`check` 会检查。
- 同步前可以取消勾选不想导入的提交，它们的编号会记进 `attempts/skip.txt`（一行一个，`#` 开头是注释），以后不再列出来。删掉一条同步来的记录时，把它的编号也写进这个文件，同步就不会再把它导回来。
- 没写编号的手写记录，如果代码和某次力扣提交一样（不算注释和空格），同步会认定是同一次，不再导入，只给它补上这三行，其余内容不动。
- 状态只升不降：有通过的提交记 `已通过`，只提交过没通过记 `尝试过`；你手动标的 `曾通过` 只有在那之后又通过了才会改。

### 5. 设置：`settings.json`（可以没有）

```json
{
  "version": 1,
  "langs": ["java", "python"]
}
```

- `langs` 是你的常用语言，写语言目录名（见上面的表），第一个是默认语言。网站上的题解和演示里的代码按它显示。
- 在网站右上角的语言菜单里改，网站会替你写这个文件；没有这个文件时默认是 Python。
- 官方题解目前有 Python、Java、C++、Go、JavaScript、TypeScript 六种语言，写了别的语言网站会忽略。

## 不要做的事

- 不要改 `progress.json` 的整体结构，也不要删掉 `version` 字段。
- 不要把账号、密码、令牌之类的东西提交进来——仓库公开的话，谁都看得到。
